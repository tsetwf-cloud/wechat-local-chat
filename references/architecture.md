# 架构与数据处理流程

项目通过一个已安装的 Skill 和 `scripts/chat.py` 命令入口工作。Python 与原生模块负责采集、筛选、归档和检查；当前 AI 负责分析，不另设 Python 后台推理服务。

## 从请求到报告

```text
账号所有者指定会话名称、时间和任务
        ↓
SKILL.md 规则与当前 Agent
        ↓ 通过终端调用
chat.py 命令入口
        ↓
runtime.py：私有环境设置、运行环境与编译器
run_selected.py：采集适配器
        ↓
native/src/Main.cs + Probe.cs + Runtime.cs
        ↓
私有主数据库快照
        ↓
business.py：精确身份与时间筛选、请求编排
selected_chat.py：分片查询、解码、稳定 ID 与持久化
        ↓
workflow.py：版本、变更、锁、哈希与当前版本指针的原子更新
        ↓
business.py 的 context：生成筛选后的证据 JSON
        ↓
当前已获授权的 AI 分析并生成本地草稿
        ↓
save-analysis：检查引用，保存 report.md + metadata.json
```

## 安装位置与私有数据

源码可以安装在任意位置，也可以从其他工作目录调用。`config.json` 和所有数据保存在独立的私有根目录，不放入已安装的 Skill 或 Git 仓库。

需要覆盖默认根目录时，每次调用都应使用 `--root`，并将它放在子命令之前。`config.example.json` 不包含真实账号或源路径。

## 请求、版本与历史记录

相同账号、联系人和时间范围的重复请求共用一个版本序列。每个请求 ID 固定对应某一代数据，并记录该代产物的哈希；不同范围不会相互覆盖。新一代产物发布失败时，不会替换之前成功的版本。

后续采集中缺失的行，不能作为消息已被删除的证据。历史内容仍保留在 SQLite 和先前版本中，但当前采集不再包含的内容，不得重新作为当前证据呈现。

## 组件之间的边界

解密器一次处理一个数据库，可以在不使用 AI 的情况下独立运行。Skill 将它接入指定会话、时间范围和任务的工作流程，并要求分析遵守消息引用与范围规则。

项目不需要单独的安全 Skill、外部提取服务、基于令牌授权的本地 HTTP 服务器、微信消息发送 API、cron 定时任务或 Wiki。
