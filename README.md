# 微信聊天查询与整理

用 AI 搜索你自己的微信聊天，找回以前的决定、整理待办，并保存成一份附有原消息引用的报告。

这是一个 AI Skill，包含操作说明和本地脚本，供 AI 助手调用，不是独立的聊天软件。

[看演示](#看一个例子) · [安装](#安装) · [怎么用](#怎么用) · [隐私说明](#隐私与数据保存)

## 能帮你做什么

- 找回之前说定的事：例如某个需求最后怎么决定、某项安排有没有确认。
- 整理一段聊天：区分已经确定的行动、个人建议和还没解决的问题。
- 查找关键词：只返回相关消息，也可以不做总结。
- 继续追问：在同一批已保存的聊天中换个问题，不必每次重新读取微信。

结果会保存为 Markdown 报告，附上相关原消息的引用，方便核对。聊天记录也会保存在本地，供后续查询；新结果不会覆盖旧报告。

**使用范围：**只处理你本人账号中、你有权处理的聊天。它不恢复已删除消息，不识别图片、语音、视频或附件正文，也不自动监控全部会话、发送微信消息或把报告发布到网上。

## 安装

### 使用前准备

目前已实测的真实聊天读取方式是：**Windows x64 上登录本人微信 4.1.15.56 x64，通过 WSL 中的 Python 调用 Windows 程序。**

- 需要 Python 3.11+、可用的 WSL Windows 互操作，以及 Windows 自带的 .NET Framework 编译器。
- **其他微信版本会被程序拒绝。**不要通过修改版本检查来强行运行。
- 原生 Windows Python 和其他 AI 助手的安装方式尚未完成真实聊天读取验证。普通 Linux 可以处理虚构示例或已获授权保存的聊天，不能直接读取 Windows 微信进程。
- 首次配置会下载 `zstandard==0.25.0` 依赖。不需要提供微信密码，也不会把解密密钥保存到配置文件。
- 如果使用云端 AI，选出的聊天内容会发送给该 AI 服务。处理真实聊天前，请先读[隐私与数据保存](#隐私与数据保存)。AI 服务的账号、联网与费用按你现有的使用方式处理，本项目不提供模型服务。

### 在 Hermes 中安装

已安装 Hermes 时，在终端执行：

```bash
hermes skills install tsetwf-cloud/wechat-local-chat// --yes
```

结尾的 `//` 不是笔误，用来选择仓库根目录中的完整 Skill。安装应包含说明、脚本、参考文档、测试和示例，不能只下载 `SKILL.md`。如果安装被源码审查拦截，先查看原因，不要用 `--force` 绕过。

如果安装命令长时间没有响应，也可以先下载完整仓库。在 Linux/WSL 的 Bash 终端执行（目标目录须不存在）：

```bash
git clone --depth 1 https://github.com/tsetwf-cloud/wechat-local-chat.git "$HOME/wechat-local-chat"
```

然后在 AI 对话中说明下载位置，让助手先读取其中的 `SKILL.md`，再按文件里的步骤操作。这个方式不会自动把 Skill 注册到助手中，不能省略读取文件。本次已完成完整仓库下载和本地测试；Hermes 联网安装命令在当前环境超时，未完成本轮全新安装验证。[查看验证记录](references/verification.md)

使用其他 AI 助手时，也可以按“完整下载 → 读取 `SKILL.md`”的方式开始；但能否调用本地工具、能否读取真实聊天，仍需要分别验证。

### 先试示例，再配置自己的账号

建议先按[示例说明](examples/README.md)运行虚构数据，看看输出是否符合预期。示例在 Linux/WSL 终端中运行，不需要配置微信账号。

需要处理自己的聊天时，在新的 AI 对话中输入下面这段话，**不是在终端执行**：

```text
使用 wechat-local-chat，帮我完成首次配置。
先检查环境，请我确认本人的账号和准确的 db_storage 目录，
再安装必要依赖、编译并测试本地程序。配置和数据保存在安装包之外。
暂时不要读取任何聊天。
```

AI 会先确认你的账号和微信数据目录，再检查运行环境。完成配置不代表已经读取聊天；下一步由你指定联系人、日期和任务。

## 怎么用

以下提示词发给已加载该 Skill 的 AI 助手。把尖括号中的内容换成实际联系人或日期，不要原样保留。

### 整理一段聊天中的待办

```text
使用 wechat-local-chat，读取我与<联系人准确名称>从<开始日期>到<结束日期>的聊天，时区为 UTC+8。
帮我整理已经说定的事、接下来要做的事，以及还没确认的问题。
附上相关原消息的引用，保存为本地 Markdown 报告。
聊天里没有明确说的责任人或截止日期，不要猜。
最后告诉我报告保存在哪里，以及哪些消息可能没有读到。
```

完成后，AI 会给出本次查询的编号和报告路径。打开报告，先核对联系人、日期、读取时间，再查看结论及其消息引用。联系人重名时，AI 应先请你确认，不能自行选第一个。

日期写成 `YYYY-MM-DD` 时，结束日期包含当天；如果精确到时分秒，则不包含结束时刻本身。

### 只找关键词，不做总结

```text
使用上一次查询<请求编号>保存的聊天，不要重新读取微信。
只查找包含“<关键词>”原文的消息，列出消息内容、时间和引用，不做分析。
```

这里的“请求编号”是上一次查询返回的 `request_id`。没找到，只说明这批已保存的聊天里没有匹配，不能据此断言全部微信历史都没有。

### 在同一批聊天里继续追问

```text
使用查询<请求编号>保存的聊天，不重新读取微信，也不扩大联系人或日期范围。
帮我区分哪些决定已经确认、哪些只是个人建议、哪些问题还没答复。
引用相关消息，另存一份新报告，保留原报告。
```

## 隐私与数据保存

**本地读取不等于全程离线。**聊天读取、解密、搜索和文件保存由本地脚本完成；脚本本身不上传聊天、不发送微信消息，也不调用模型。但你使用云端 AI 助手时，筛选出的消息仍会进入它的上下文并发送给服务商。

还需要注意：

- 读取时会复制相关联系人数据库和消息数据库，**底层副本可能包含其他会话**，不只是所选联系人的数据。AI 按规则只读取你指定范围的消息；这不是文件系统层面的隔离。
- 配置、加密副本、解密后的明文、聊天归档和报告保存在安装包之外的私有目录，**不会自动清理**。这些文件需要你自行保管；访问权限限制不等于加密，也不能防止管理员或已被入侵的主机访问。
- 解密密钥只在运行时内存中使用，不有意写入配置或日志；内存清理不能承诺彻底擦除。
- 报告附有消息引用，程序会检查引用是否来自本次查询，但**不会替你判断 AI 的理解是否正确**。重要决定仍应回看原消息。

[完整安全说明](references/security.md)

## 哪些内容可能读不到

- 刚收到、还没写入主数据库的消息可能缺失，等待固定时长也不能保证补齐。
- 只在手机上、尚未同步到电脑的聊天，已删除消息，以及图片、语音、视频和附件正文，不在读取范围内。文件名不代表附件内容。
- 文件完整性检查不能证明历史记录完整，也不能保证多个数据库恰好来自同一时刻。

程序不会自动提权、注入或写入微信源数据库，不会为补齐消息强制刷新数据库，也不会自动定时采集、上传报告或导入知识库。

**旧版本提醒：**0.1.0 在部分情况下可能把历史消息混入当前结果，0.1.1 已修复。旧报告不会自动修正；如果曾用 0.1.0 生成报告，应在你确认的范围内重新读取并生成报告。[修复与验证记录](references/verification.md)
